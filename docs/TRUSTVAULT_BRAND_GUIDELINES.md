# Purpose

The TrustVault Brand Guidelines define the official visual, verbal and experiential identity of the TrustVault ecosystem.

This document ensures that every interface, illustration, animation, marketing asset, social media post, document and future product follows a single, consistent brand language.

These guidelines apply to:

- Website
- Marketplace
- Checkout
- Gift Vault
- Seller Storefront
- Dashboard
- Mobile Applications
- Documentation
- Marketing
- Social Media
- Future TrustVault Products

This document should be considered the primary source of truth for the TrustVault brand.

Whenever uncertainty exists, these guidelines take precedence.

---

# Vision

TrustVault exists to become the most trusted marketplace ecosystem on the internet.

Our objective is not simply to build another e-commerce platform.

Our objective is to create a marketplace where buyers and sellers immediately feel protected, confident and respected.

Trust should be felt before it is read.

Every interaction should reinforce three core emotions:

- Security
- Confidence
- Simplicity

TrustVault combines premium design with secure technology to deliver an experience that feels effortless while remaining dependable.

# Clear Space

Maintain generous clear space around all TrustVault logos.

No text, icons or illustrations should crowd the logo.

Atlas should never overlap the logo.

The logo should remain readable at all sizes.

---

# Minimum Sizes

Digital:

Primary logo should remain clearly legible at all supported screen sizes.

Do not reduce the logo to a size where the wordmark becomes difficult to read.

For favicons and application icons, use the TrustVault Shield only.

---

# Background Usage

Preferred backgrounds:

- Black
- White
- Graphite
- Charcoal

Use sufficient contrast at all times.

Avoid placing the logo over busy photography.

If necessary, apply a subtle overlay behind the logo to preserve readability.

---

# Incorrect Usage

Never:

- Stretch the logo.
- Rotate the logo.
- Add shadows to the logo.
- Add outlines.
- Change colours.
- Modify proportions.
- Animate the logo unnecessarily.
- Place Atlas on top of the logo.
- Combine TrustVault and Arc into a single logo.
- Use unofficial logo variations.

Consistency builds recognition and trust.

# Quality Standards, Accessibility & Brand Governance

## Brand Consistency

Every new feature, page, illustration, animation or marketing asset must reinforce the TrustVault identity.

Consistency is more valuable than novelty.

If a new design introduces unnecessary variation, it should be reconsidered.

Every contribution should feel like it belongs to the same product family.

---

# Accessibility Standards

Accessibility is a non-negotiable product requirement.

Every TrustVault experience should support:

- Semantic HTML
- Keyboard navigation
- Screen readers
- Sufficient colour contrast
- Visible focus indicators
- Reduced motion preferences
- Responsive typography
- Accessible forms
- Meaningful alternative text

Accessibility should be considered during design—not added afterwards.

---

# Performance Standards

Performance is part of the TrustVault brand.

Design decisions should contribute to excellent user experience.

Guiding principles include:

- Optimised SVG assets where practical
- Optimised WebP and PNG imagery
- Lazy loading where appropriate
- Efficient animations
- Minimal layout shifts
- Responsive image delivery
- Small JavaScript bundles
- Fast page rendering

Performance should never be sacrificed for unnecessary visual effects.

---

# Lighthouse Goals

TrustVault aims to achieve excellent quality across all core Lighthouse metrics.

Target scores:

Performance: 95–100

Accessibility: 100

Best Practices: 100

SEO: 100

These goals should guide design and engineering decisions while recognising that carefully chosen third-party integrations may occasionally influence individual scores.

# Definition of Done

A design or interface should be considered complete when:

- It aligns with the TrustVault brand.
- It follows the Atlas Design Bible.
- It respects Arc brand guidance where applicable.
- Accessibility has been reviewed.
- Performance has been considered.
- Responsive behaviour has been verified.
- Documentation has been updated when required.
- Assets follow the approved naming conventions.
